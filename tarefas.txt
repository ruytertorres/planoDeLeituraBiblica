2️⃣ O QUE FOI FEITO — CAMADA DE ARQUITETURA (CONCLUÍDO)
✅ PASSO 1 — CONTRATO DE PLANO (ESSENCIAL)

Status: FEITO
Arquivo:

/js/dominio/planos/contrato_plano.js


Responsabilidade clara:

Não implementa plano

Documenta o shape

Valida em runtime

Gera erro explícito se o contrato for violado

Contrato lógico garantido:

{
  id: string,
  nome: string,
  descricao: string,
  totalDias: number,
  dias: Dia[],

  getDia(numero): Dia | null,
  getDias(): Dia[]
}


Decisão crítica registrada:

PlanoManager nunca confia em planos sem validação

Falha rápida > bug silencioso

Esse ponto é fundamental para evolução futura.

✅ PASSO 2 — NORMALIZAÇÃO DO DIA (DOMÍNIO)

Status: FEITO

Correção arquitetural aplicada:

A UI não acessa mais estrutura interna

O Dia expõe intenção, não dados crus

Métodos confirmados e utilizados:

getAntigoTestamento()

getNovoTestamento()

temLeitura()

getResumo()

Benefício direto:

Mudanças internas não quebram a UI

Suporte futuro a planos temáticos, leituras extras, paralelas, etc.

✅ PASSO 3 — PLANO MANAGER (PEÇA-CHAVE)

Status: FEITO
Arquivo:

/js/infra/plano_manager.js


Responsabilidades bem delimitadas:

Registrar planos

Validar contrato

Definir plano ativo

Expor plano ativo

Regras respeitadas:

Não renderiza

Não persiste progresso

Não conhece UI

Fluxo correto consolidado:

main.js → PlanoManager → Plano Ativo → Dia


Resultado:

main.js não conhece planos concretos

Infraestrutura pronta para múltiplos planos sem refatoração
